## Rules this file is held to

1. **Every number originates in a `runs/<run_id>/metrics.json` produced on the owner's machine.**
   Nothing is estimated, rounded up, carried over from the notebook, or taken from a paper. A number
   that cannot be re-derived by the documented command is deleted, not footnoted.
2. **Every row names the config that produced it.** Mixing a `dev`-config baseline with a
   `default`-config transformer in one table without labelling both is the failure mode this repo
   exists to avoid.
3. **Accuracy carries a Wilson 95% interval.** The default test set is 1,000 examples, giving roughly
   a ±1.5 pp interval. A bare point estimate at that sample size is misleading.
4. **The two models are compared with an exact McNemar test**, because they are evaluated on the same
   examples and the predictions are paired. Two independent proportion tests would be the wrong test.
5. **A null result is a legitimate outcome.** If the TF-IDF control lands within the confidence
   interval of the fine-tuned transformer, that is the finding and it gets reported as such, in plain
   English, above the table.

## Baseline preprocessing ablation

The control's preprocessing chain in the original notebook was: lowercase → keep only `^\w+$` tokens
→ remove NLTK English stopwords → Porter stem, then unigram TF-IDF. That chain deletes negation:
`not`, `no` and `nor` are NLTK English stopwords, and the `^\w+$` filter destroys contractions such
as `n't` before the stopword filter even runs. With `ngram_range=(1,1)` no bigram can recover it. So
`"not good"` and `"good"` collapse to the same feature vector — on the one task where negation is
decisive.

This grid measures how much that costs. All four cells are published whatever they show.
